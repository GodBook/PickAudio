# 拾音 PickAudio

Android 本地与在线音乐播放器，使用 Kotlin、Jetpack Compose、Room、Media3 和内嵌 QuickJS。无账号设计，歌单、收藏和设置在设备上保存。

当前源码为 v1.4.3/code 16，新增按 QQ 原曲编号解析并检查音频的「拾音 QQ 直连」默认源，设置改为六个分类页面，搜索试听后返回原结果页并保留滚动位置，见 [更新说明](docs/RELEASE-1.4.3.md)。保留 Android 16 播放恢复、星澜聚合备用源和六种可保存的主题配色。歌曲可用性仍受平台授权与音源后端影响。

## 主要功能

- QQ 默认使用「拾音 QQ 直连」，网易云默认使用星澜 v3.2.0。升级自动替换旧 QQ 默认线路一次，保留自定义绑定、明确停用与后续手动选择；音乐源管理可选择备用线路或自行导入脚本。
- 设置首页提供外观、播放与下载、歌词、存储与缓存、备份与恢复、关于拾音六个分类和当前值摘要；详细设置独立显示，歌词字号有即时预览。
- 设置 → 外观支持雾蓝、松绿、鸢紫、玫瑰、琥珀、青碧六种配色，每种适配深浅模式、即时生效并保存到偏好与备份。
- “导入音乐”统一提供扫描手机音频、多选文件和文件夹递归导入；显示进度和新增／跳过／失败统计，支持取消，保留已导入歌曲。
- 音乐库只展示主动加入或导入的歌曲，试听、喜欢、歌单和下载不会自动加入；支持歌手、专辑、文件夹、最近播放分类和歌曲／歌手／时长／添加时间排序。
- 网易云与 QQ 分别搜索、分页和重试；试听后返回仍保留查询、平台、结果和滚动位置。平台故障不会隐藏另一方结果，取消或过期请求不会覆盖新查询。
- 歌曲可批量加入歌单、下载或加入队列；加入歌单时可直接新建。歌单成员、自建歌单和播放队列可拖动排序，清空队列可撤销。
- 顺序、列表循环、单曲循环和随机播放；后台媒体通知、耳机／蓝牙断开暂停、进度恢复和睡眠定时。播放器显示解析、缓冲和失败状态，提供重试、换源与失效文件重新关联。
- QQ 原版本不可用时提供其他平台候选歌曲，需要用户确认；不会静默替换为搜索到的其他录音。
- 音质偏好可修改并实际应用，下载音质按音源声明的能力筛选。下载检测真实容器、FLAC 位深和可解码性，不将有损音频伪装成无损。
- 在线歌词与翻译缓存；手动 LRC、文件夹同名 LRC、每首歌独立校准、字号和翻译开关。手动浏览后恢复跟随，也可直接回到当前歌词。
- Android UIDT 系统下载任务，最多同时处理两首。显示中文状态、速度和预计剩余时间；支持批量暂停、继续、重试、取消，以及完成后播放或打开文件。
- 默认仅 Wi-Fi 下载，可在设置中允许移动网络。中断时保留进度；仅在服务器资源标识和 Range 匹配时续传，无法确认时重新完整下载。
- 完成的歌曲发布到公共 `Music/PickAudio`。临时下载放在应用私有文件目录，与可清理的缓存分开。
- 分类清理音频、封面和无任务的临时下载文件；保留正式下载、歌单、收藏、手动歌词和暂停任务的进度。

## 音乐源与音质

| 来源 | 能力与限制 |
|---|---|
| 拾音 QQ 直连（QQ 默认） | 通过落月公开接口按原曲 MID 请求标准／高品质／FLAC，校验返回 MID 和音频文件头，拒绝试听片段与无效内容。实际编码和码率以播放器检测为准 |
| 内置星澜 StellarWave v3.2.0（网易云默认、QQ 备用） | 随 APK 提供 LX 脚本并修正 QQ 文件编号使用，原作者及许可注释保留；声明 128K／320K／FLAC，实际音质与歌曲可用性以请求和文件检测为准 |
| 内置网易云线路 | 标准／高品质请求，实际音质以播放器或下载校验结果为准，不宣称提供无损 |
| 内置 QQ 处理 | 优先请求 QQ 原曲地址，平台拒绝匿名播放时可配置 QQ 音源或手动确认网易云候选录音 |
| 自定义 LX 移动版脚本 | 通过本地 JS 或 HTTPS 链接导入，按初始化声明的平台与音质提供选择，支持兼容性测试 |

脚本导入后可选择绑定平台。升级仅在首次引入新默认源时替换旧的默认内置线路，保留自定义源和明确停用的平台状态；之后主动选回备用线路不会被重启覆盖。QQ 直连的连接测试会实际解析样本并检查音频内容；脚本初始化通过不代表每首歌曲都可用。外部平台、音源和网络的可用性以实际请求为准。支持正版音乐。

## 备份和升级

备份是带版本与 SHA-256 校验的 ZIP，包含歌单、收藏、歌曲记录、歌词及校准、偏好设置和音源描述；不包含音频文件与完整音源脚本。恢复前展示内容，恢复后展示统计和需要重新关联的本地文件。相同歌单增量合并，重复恢复不会复制歌单。

v1.2.0 将 Room 数据库从 v1 迁移至 v2，保留已有歌曲、成员、收藏、下载和歌词。歌曲、歌单及脚本更新采用 Upsert，避免替换记录引发关联删除。旧版 v1 备份仍可导入。

v1.3.0提供v2→v3→v4迁移，增加独立收藏排序、队列条目和可恢复操作字段，以及真实音频信息和文件身份；备份v3兼容v1/v2格式，恢复中断后可继续。待修复文件从曲库持久状态读取，候选关联须人工核对。

v1.3.2 提供 v4→v5 迁移，独立保存曲库归属。旧的纯在线试听记录从曲库视图隐藏，本地音频保留；歌曲记录、歌单、喜欢、队列与下载仍保存。备份同时保存曲库标记，恢复不会把试听记录重新加入曲库。

## 运行和验证

要求 Android 16（API 36）；支持 arm64-v8a 和 x86_64，原生库按 16KB 对齐。开发环境使用 JDK 17、API 36 SDK、NDK 28.2.13676358 和 CMake 3.22.1。

```powershell
$env:JAVA_HOME = 'D:/dev/jdk-17'
./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
./gradlew.bat :app:assembleRelease
./gradlew.bat :app:lintDebug
```

Android 流程测试只在没有个人数据的专用 API 36 模拟器运行；部分测试会清空应用队列。设备命令见构建与发布基线，当前本地设备明确指定emulator-5560。测试覆盖搜索竞态／分页、歌曲版本、音频格式／续传策略、Room 迁移、扫描设置、歌词、备份、下载与界面流程；本轮实际结果见优化执行记录。Windows 中文路径下 JVM 测试使用临时 ASCII 运行路径，不移动项目。

Debug APK：`app/build/outputs/apk/debug/app-debug.apk`。Release 构建默认生成未签名 APK，使用原项目签名后才能覆盖安装旧正式版；签名密码不写入项目文件。

Release已开启R8与资源裁剪。构建版本统一读取version.properties；依赖锁定和SHA-256校验随本轮验收生成。第三方来源与完整许可证见[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，构建同时将准确依赖清单和原始notice放入APK，设置页可离线查看。

正式安装包：[`PickAudio-v1.4.2-release.apk`](https://github.com/GodBook/PickAudio/releases/download/v1.4.2/PickAudio-v1.4.2-release.apk)，沿用原项目签名，大小约 7.85 MiB，可覆盖旧正式版。更新说明和安装包校验信息见 [v1.4.2 Release](https://github.com/GodBook/PickAudio/releases/tag/v1.4.2)，构建、播放回归及覆盖升级数据保留结果见 [修复与发布记录](docs/BUGFIX-QQ-PLAYBACK-1.4.2.md)。
