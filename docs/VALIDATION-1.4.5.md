# v1.4.5 随机播放稳定性验证

日期：2026-10-09。用户报告随机播放偶发歌曲停止、应用无响应，触摸后退出。本轮未取得用户设备的原始 ANR/崩溃堆栈，以下记录区分代码缺陷复现和设备验证范围。

## 缺陷依据与修复

原 `QueueTimeline` 只对当前条目改写随机上一首/下一首，其余条目及首尾仍采用顺序索引；同时忽略 `REPEAT_MODE_OFF` 的末尾终止规则。三条队列处在最后一项时，遍历可能得到 `0→1→2→1→2…`，单条随机队列也会得到 `0→0…`。Media3 1.4.1 的 `Timeline.equals()`/`hashCode()` 包含无步数上限的遍历，部分组合会卡住主线程；序列化还可能输出重复或无效窗口索引。

四项有步数上限的设备回归在原 v1.4.4 代码全部失败，明确报告时间线环路，未让测试本身陷入无限循环。修复版的五项时间线专项通过，覆盖完整正向/反向顺序、单曲与空队列、24 次队列推进、Media3 比较/哈希/序列化、重复歌曲、编辑与模式变更，以及旧快照的时长和顺序不变。

修复从实际待播池和播放历史生成覆盖全部条目的排列，固定时间线快照的当前时长，统一首尾和正反索引。随机列表在不循环时能够终止，循环模式按 Media3 规则重复。手动选择歌曲时移除待播池中的当前条目，播放模式变更通知控制器更新列表。数据库仍为 v5，无删库或迁移变更。

## 本地构建与环境

84 项 JVM 测试，失败、错误和跳过均为零。Debug、Release、测试 APK 构建、Lint 与 Room schema 检查通过。

设备测试只在专用 `PickAudio_Playback_API36_20261008` / `emulator-5560`、API 36 x86_64 模拟器执行。原测试实例数据先归档到 `app/build/release-1.4.5/before-device.tgz`，未操作其他项目模拟器或用户实体设备。

首轮 17 项专项中，14 项通过，3 项界面检查失败：模拟器锁屏和 SystemUI 的未响应界面阻止 Activity 回到 RESUMED，Compose 层级也不可见。启动日志同时记录多个系统进程启动超时，时间早于拾音测试；应用退出记录仅为 instrumentation 完成后的主动停止。首轮日志保留为 `first-device-regression.log`，系统日志为 `system-ui-anr.txt`。专用设备重启、禁用测试锁屏并确认桌面获得焦点后重新执行完整回归。

重启后的完整 Debug 设备回归 **90 项全部通过**，失败与跳过均为零，记录为 `full-debug-device.log`。包含上述首轮失败的三项检查、24 次真实自然随机切歌、后台前台服务与媒体控制器状态、暂停/恢复、回到界面，以及既有断线续播、快速取消、焦点中断、QQ 失败跳歌、迁移、备份、下载、来源生命周期和界面流程。随机队列含重复歌曲条目，检查每次切歌及每轮待播池的条目身份。
