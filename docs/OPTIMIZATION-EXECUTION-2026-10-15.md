## 证据与运行

当前及后续原始日志保存在 `app/build/release-1.5.0/`。JDK 17、SDK 36、NDK 28.2、CMake 3.22.1；常规命令与签名/升级要求沿用 [构建与发布基线](BUILD-AND-RELEASE.md)。不将凭据、手机数据或临时音频提交仓库。

手机基线：仅放宽 minSdk 的 v1.4.5 Debug，10,000 首曲库/20 首歌单查询专项通过；批量队列 1,000→2,000 条五次主线程样本为 542.7/547.3/558.6/552.2/548.6 ms。首轮新版五次为 30.5/32.2/21.2/22.3/18.4 ms，属于初步样本，最终须在固定构建上扩大采样。日志：`baseline-queue.log`、`baseline-performance.log`、`after-performance.log`。

首轮新增 7 项手机专项中 5 项通过、2 项失败：构建期间继续修改了 DAO 返回值和测试 Provider 统计，导致主 APK 仍含旧接口/Provider，而新测试已编入测试 APK。失败保留于 `first-device-specialists.log`；必须冻结源码后成对重建并重跑，不能把这次结果作为最终验收。旧版性能基线第一次曾遇到测试方法返回类型不是 void，修正测试后已重新通过，保留初轮日志。

固定构建首轮完整手机回归：102 项执行，98 项通过、4 项失败。新增七项后端专项全部通过；其余失败分别为 API 36 安装夹具不适配 API 35、媒体 URI 改变后停滞监测未重启、旧测试仍要求跨隐藏结果全选 41 首、帧采集清理重复移除监听器。已修正并进行定向复验，原失败日志保留 `full-debug-device.log`。帧样本受 Debug、全组压力及测试驱动影响，不能作最终帧率宣称；待独立裁剪包测量。后续版本的媒体会话还增加懒加载媒体信息和 UID 索引，减少大队列重复构造。

发布取舍：N09 的下一首预解析/连续媒体准备暂不启用，以免扩大移动数据消耗及改变候选录音确认；N15 保持既有缓冲时长，改为按本地/远程选择 wake 和停滞监测；USB 充电测试不能证明续航提升。N16 采用本轮可在用户真机运行的 FrameMetrics、am start -W、主线程 API 计时及分阶段播放指标，记录调试/裁剪构建差异。Baseline Profile 与长时间脱离 USB 的配对耗电实验后续独立实施，不作为已完成项。
