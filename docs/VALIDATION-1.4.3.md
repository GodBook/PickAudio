# v1.4.3 验证记录

验证日期：2026-10-08。版本：1.4.3/code 16，Room 数据库仍为 v5。

## QQ 默认源

新增原生「拾音 QQ 直连」，使用落月公开接口的原曲 MID 解析。请求的标准、高品质、FLAC 档位分别映射为服务端 4、8、10；服务返回的 `songMID` 必须与请求一致。解析后检查前段音频文件头，拒绝 RS 试听片段、错误歌曲、失效地址与非音频内容。原默认线路只在首次引入新源时迁移，自定义绑定、明确停用、被停用的旧源与之后的手动选择保留。

真实样本的六组 Range 请求全部 HTTP 206，文件头与完整文件大小一致：

| 样本 | 标准档 | 高品质档 | FLAC 档 |
|---|---|---|---|
| Faded，`002NkERn2LNVI4` | AAC，约 192 kbps，5,142,344 字节 | MP3，320 kbps，8,507,195 字节 | FLAC，约 1,016 kbps，27,001,869 字节 |
| 晴天，`0039MnYb0qxYhV` | AAC，约 191 kbps，6,519,764 字节 | MP3，320 kbps，10,792,943 字节 | FLAC，约 1,644 kbps，55,397,039 字节 |

标准档当前交付高于 128K 偏好的 AAC；播放器显示实际音频信息，下载按真实编码与格式验证。FLAC 响应的 MIME 与实际文件头不一致，文件头确认为 `fLaC`，不能只凭 MIME 判断音质。样本记录在 `app/build/release-1.4.3/live-source-probes.json`。

公网样本检查在主机执行。本地模拟器网络的 DNS 返回保留地址，被生产网络策略拒绝，因此不宣称已在该网络完成 QQ 公网样本的整曲播放。Media3 解码、QQ 原曲身份传递、播放恢复与界面流程通过设备回归验证；歌曲和服务可用性仍以用户实际网络与平台授权为准。
