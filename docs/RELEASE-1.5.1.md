# 拾音 PickAudio v1.5.1

修复部分 QQ 歌曲只能播放或下载前半段时，被应用误认为完整歌曲的问题，并自动检查、重新下载不完整歌曲。

- 对比 QQ 原曲时长与音频实际时长，拒绝合法但明显过短的试听片段。
- 检查解码后的实际音频末尾，识别“文件头声明整首，实际数据提前结束”的情况；顺序播放和单曲循环均生效。
- 下载、断点恢复、发布恢复与取消收尾均校验完整性，失败不会覆盖原曲时长或标记为已完成。
- 旧的短下载保留文件并标记为不可用，播放时尝试重新解析，可重新下载。用户主动导入的本地片段不受影响。
- 重试绕过已确认损坏的 QQ 音频缓存，备用官方线路拒绝明确的试听地址。
- 完整的 QQ 单曲循环复用现有音频和缓存，避免每轮重新请求音源。
- 修复旧后台播放服务的迟到销毁回调取消新重试的时序问题。
- 应用回到前台或播放发现旧下载异常时，检查应用已完成的下载；确认不完整后按原音质加入重下队列，沿用仅 Wi-Fi 设置。下载页提供“检查下载完整性”按钮和处理状态。
- 已通过且文件未变化的歌曲复用检查结果；旧文件不自动删除，读取异常或未知时长不会直接判为半首。暂停、取消和已失败任务不会自动恢复；音源继续失败或不支持原音质时留在“需处理”，不无限自动重试。

版本为 1.5.1/code 20，数据库保持 v5，支持 Android 15/API 35 及以上。实际音质和歌曲可用性仍取决于平台授权及音源；接口拒绝时会提示重试或换源，不替换其他录音。

2026-11-12 按使用者要求改用新签名发布 [可安装包](https://github.com/GodBook/PickAudio/releases/tag/v1.5.1)，资产为 `PickAudio-v1.5.1-release.apk`，替换此前的未签名构建。新签名无法覆盖旧版 v1.5.0：请先在旧版“设置 → 备份与恢复”导出备份，并单独保存音频和自定义音源脚本，再卸载旧版、安装新包并恢复备份/重新关联文件。旧版应用内更新会拒绝不同签名，需要从 Release 页面下载安装；后续新签名版本可继续沿用同一证书升级。

新签名配置及复用方式见 [签名记录](SIGNING.md)。
