# v1.4.4 播放稳定性验证

日期：2026-10-08。用户报告环境：v1.4.3、iQOO Z10 Turbo、Android 16、QQ《青花瓷》。

## 排查与修复依据

公网查询确认原曲 MID 为 `002qU5aY3Qu24y`。同日请求 QQ 默认源时，同一 MID 和音质先出现 `code=110000` / `500011`，随后返回成功及有效音频文件头。新版本仅对临时网络/后端错误限次重试，继续验证 MID、完整音频和音质，不回退到其他歌曲。

原实现仅在 Media3 明确报告网络错误时恢复；不报错的持续缓冲没有期限。新增进度监测，20 秒无进展或 60 秒持续缓冲触发原位置恢复，复用最多两次的重试预算。暂停和焦点抑制重置监测，旧请求不能恢复新的队列条目。

原自动跳歌流程先把播放意图设为 false，延迟一秒再播放下一首，导致服务在切歌间隙退出前台。改为保持解析状态和播放意图直到下一首准备完成；明确暂停仍取消跳歌。解码就绪不再立即清零失败计数，音质不匹配也进入统一失败处理，顺序队列末尾失败不会循环到开头。

播放器创建与重置此前位于协程异常处理之外，现与解析、准备共用错误边界。系统退出记录加入用户主动导出的诊断文件，以便核对 OEM 设备的进程终止原因。

## 验证环境与限制

设备回归仅在专用 `PickAudio_Playback_API36_20261008` API 36 x86_64 模拟器执行。测试会替换专用测试应用队列，未操作用户实体设备或其他项目模拟器。原测试数据先归档于本地构建目录。

本地模拟器系统 DNS 返回 `198.18.*` 保留地址，生产网络策略正确拒绝；错误后进程仍存活。该结果不能当作 QQ 公网整曲播放通过，也未复现 iQOO 上的相同闪退堆栈。QQ 公网样本与可控故障回归分别记录，不推断所有平台歌曲永远可用。

完整构建、回归与发布结果将在验收后写入本记录。
